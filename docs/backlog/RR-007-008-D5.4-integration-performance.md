# RR-007 / RR-008 D5.4 — Integration and performance validation

## Objective

Validate the integrated D5 pipeline across RR-007 world streaming/pooling (D5.1), RR-008 retreat/stagger/squad coordination (D5.2), and RR-007 runtime encounter spawning (D5.3).

## Automated coverage

- `tests/world_encounter_integration_test.gd` exercises authored segment validation, world generation, encounter-plan materialization, enemy/archetype and squad wiring, damage reception, streaming-triggered segment recycling, encounter release, bounded enemy/segment pools, and generation-reset cleanup.
- `tests/world_encounter_performance_test.gd` repeats seeded generation and streaming 20 times. It reports average and p95 microsecond timings for the CI host and asserts bounded active-segment and pool counts.
- Existing D5.1, D5.2, D5.3, encounter director, AI, combat and streaming tests remain in CI.

## Performance interpretation

CI timing output is a repeatable regression diagnostic for the GitHub runner only. It is not a mobile performance baseline and must not be used to claim 60 FPS, CPU budgets, memory budgets, or Android/iOS readiness. Wall-clock limits are intentionally not hard-gated in shared CI because runner contention makes them nondeterministic.

## Device profiling required for acceptance

Record at least three cold and three warm runs on each representative device:
- Low-tier Android: target 30 FPS; capture frame-time p50/p95/p99, main-thread and physics-thread time, active enemies, active segments, object/pool counts, and peak memory.
- Mid-tier Android: target 60 FPS; capture the same metrics.
- iOS representative device: capture the same metrics and thermal behavior.
- Profile a sustained stream with at least 20 active combatants (or the authored cap if lower), repeated segment recycling, and one full encounter including stagger/retreat/death.
- Save device model, OS, Godot build, renderer, resolution, quality settings, seed, run duration, profiler captures and measured results under `docs/performance/d5-4/`.

## Acceptance criteria

1. All deterministic D5.1–D5.3 and D5.4 CI tests pass.
2. End-to-end integration proves that segment recycle releases its encounter and subsequent streaming keeps active entities and pools bounded.
3. Performance smoke test emits average/p95 CI-host timings over 20 deterministic iterations without imposing unstable wall-clock gates.
4. Android and iOS device evidence is recorded separately before mobile performance sign-off. Until then, performance status remains **CI diagnostic only; device validation open**.
5. No remote AI or nondeterministic network dependency is introduced into runtime combat or streaming.
